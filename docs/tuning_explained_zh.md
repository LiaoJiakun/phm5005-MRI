# 调参说明（答辩用）

分支 `experiment/oasis1-10slice-tuned`。代码：`scripts/tune_10slice.py`（运行）、`scripts/analyze_tuning.py`（表格和图）。结果：`results/oasis1_10slice_tuned/`。

## 一句话

在**不碰测试折**的前提下，用**嵌套交叉验证**从事先定好的少数几组参数里选参数，再用 3 个随机种子的平均预测作为最终模型；报告的是外层测试折上的成绩，和没调参的主结果用**同一批折、同一批人**比较。

## 1. 为什么要调参

主 notebook 的参数是项目一开始定下的常用值，没调过。结果里有两个明确信号：

* ResNet18 多数折在第 1–2 个 epoch 就到达最低验证损失，说明学习率 1e-4 对 158 个训练样本可能偏大、模型很快过拟合；
* 学习率调度器设置了但从未生效。

所以调参的目标是：针对这些信号，试几组**有理由的**替代设置，看能否在不作弊的前提下提高测试成绩。

## 2. 候选参数（运行前固定，之后没有增改）

| 名称 | 改了什么 | 理由（答辩时这样说） |
|---|---|---|
| R1_base | 主 notebook 的设置（lr 1e-4，最多 20 轮，patience 5） | 参照组，候选里包含原设置，调参才可能"选回原设置" |
| R2_lr3e-5 | 学习率降到 3e-5；最多 30 轮，patience 7；学习率在验证损失 2 轮不降时减半 | 早停太早 → 用更小步长、给更多轮次 |
| R3_lr1e-5 | 同上，学习率 1e-5 | 再小一档，检查是不是越小越好 |
| R4_probmean | lr 3e-5；每层切片各出一个概率，10 个概率取平均（晚期融合） | 组员用的融合方式；参数更少（512→2 而不是 5120→2），可能更不容易过拟合 |
| R5_regularised | lr 3e-5；dropout 0.5，权重衰减 1e-2，标签平滑 0.1 | 直接针对过拟合加正则 |
| R6_freeze_early | lr 3e-5；冻结 conv1 和 layer1 | 低层是通用边缘/纹理特征，冻结后可训练参数更少 |
| C1_base | CNN 主设置（lr 1e-3，最多 35 轮，patience 7） | 参照组 |
| C2_lr3e-4 | lr 3e-4，最多 50 轮，patience 10，学习率调度 | 从头训练需要更多轮次、更稳的步长 |
| C3_regularised | dropout 0.5，权重衰减 1e-3，标签平滑 0.1 | 针对过拟合 |
| C4_probmean | 每层概率平均 | 同 R4 |

为什么只有这几组、不做大网格：每折测试只有约 40 人，AUC 本身的随机波动就有 ±0.05 以上；候选越多，越容易"挑中运气最好的"。少量、有理由的候选更容易解释，也更不容易被噪声骗。

## 3. 怎么选（嵌套交叉验证）

1. **外层**：和主 notebook 完全相同的 5 折（种子 31000），每折约 40 人做测试。
2. **内层**：在每个外层折里，只用它的训练部分（约 158 人）再做 3 折交叉验证。每组候选参数在 2/3 上训练、在 1/3 上算 AUC，取 3 次平均作为这组参数的"内层分数"。
3. 每个外层折、每个模型（CNN / ResNet）、每种取层（Fixed / Canny）**各自**选内层分数最高的一组参数。
4. 用选中的参数，在该外层折的训练部分重新训练（早停用的验证集和主 notebook 相同），**3 个随机种子**各训练一次，测试折的预测取 3 个模型概率的平均。
5. 测试折只在最后用一次。

**为什么这样没有泄漏**：任何选择都只看外层训练部分；某个人当测试者的那一折里，他的标签从来没参与选参数。

## 4. 教授可能问的问题

**Q：不同折选出的参数不一样，那你的"最终模型"是哪个？**
嵌套交叉验证评估的是"整个调参流程"的表现，而不是某一组固定参数。每折选得不一样，说明哪组参数最好本身不稳定（数据小）。如果要部署，就在全部 198 人上再跑一次同样的选参流程，得到一组参数。

**Q：为什么不直接用测试成绩最高的参数？**
那样等于用测试集调参，成绩会偏高。我们另外也列出了每组参数在外层测试折上的成绩（`all_configs_outer.csv`），但只作为透明信息，明确标注"事后挑最大值是乐观的"，主结论不用它。

**Q：3 个种子取平均算不算作弊？**
不算。种子集成不看任何标签，只是减少随机初始化带来的波动，是标准做法。我们也单独报告了单个种子（和主 notebook 同一个种子）的成绩，方便看集成本身贡献了多少。

**Q：为什么用 MPS（苹果 GPU）？结果能复现吗？**
MPS 比 CPU 快约 15 倍，才可能在一晚上跑完嵌套搜索。代价是 MPS 不是逐位确定的，重跑会有很小的数值差别。主 notebook 仍然在 CPU 上、完全可复现；调参结果作为补充实验报告。

**Q：内层只有约 53 人做验证，选择可靠吗？**
不完全可靠，这正是用 3 折平均而不是单次划分的原因。仍然会有噪声，所以我们把"每折选了什么"全部公开，并说明调参带来的提升如果置信区间包含 0，就不能说调参确实有效。

**Q：调参后 Fixed 和 Canny 谁更好？**
看 `paired_fixed_vs_canny_tuned.csv`：两种取层用同样的调参流程，配对比较方法和主 notebook 相同。

**Q：为什么 CNN 要加 BatchNorm？**
课程原版 SimpleCNN 没有 BatchNorm，在 128×128 的 MRI 上完全训练不动（训练损失一直是 0.693，即 ln2）。32 人的过拟合测试中，降学习率、换初始化都没用，只有加 BatchNorm 后能学到 100% 训练准确率。这是在主 notebook 里就做的修改，调参分支沿用。

## 5. 结果

所有数字由 `scripts/analyze_tuning.py` 从保存的预测重新计算，表格在 `results/oasis1_10slice_tuned/`。外层折、受试者与主 notebook 完全相同（198 人，每人测试一次），阈值 0.5。

| 模型 | 未调参 汇总 AUC [95% CI] | 调参后（3 种子平均）汇总 AUC [95% CI] | 调参 − 未调参（配对 bootstrap 95% CI） | 调参后单种子 每折平均 AUC | 每折选中的参数 |
|---|---|---|---|---|---|
| ResNet18 固定层 | 0.703 [0.63, 0.77] | 0.738 [0.67, 0.81] | +0.035 [−0.013, +0.089] | 0.700 | R4 ×4，R2 ×1 |
| ResNet18 Canny | 0.666 [0.59, 0.74] | 0.710 [0.63, 0.78] | +0.044 [−0.018, +0.111] | 0.618 | R4 ×4，R1 ×1 |
| CNN 固定层 | 0.704 [0.63, 0.78] | 0.705 [0.63, 0.78] | +0.001 [−0.040, +0.045] | 0.713 | C4 ×5 |
| CNN Canny | 0.707 [0.63, 0.78] | 0.691 [0.62, 0.77] | −0.015 [−0.059, +0.028] | 0.675 | C4 ×2，C1 ×2，C2 ×1 |

调参后 0.5 阈值下（准确率 / 敏感度 / 特异度）：ResNet18 固定层 0.646 / 0.63 / 0.66；ResNet18 Canny 0.657 / 0.69 / 0.62；CNN 固定层 0.646 / 0.77 / 0.52；CNN Canny 0.636 / 0.74 / 0.53。

调参后 Canny − 固定层：ResNet18 −0.028 [−0.092, +0.037]，CNN −0.014 [−0.058, +0.031]，仍然没有差别。

**怎么解读（答辩时这样说）：**

* **调参没有带来可靠的提升。** 四个比较的置信区间都包含 0。ResNet18 两组汇总 AUC 提高 0.035–0.044，但不显著；CNN 基本不变。
* **ResNet18 的提升主要来自 3 种子平均，而不是选中的参数。** 只看和主 notebook 同一个种子的单个模型，调参后的 ResNet18 反而不比未调参好（固定层 0.700 vs 0.719，Canny 0.618 vs 0.667）。
* **内层最常选中的是"每层概率平均"（R4 / C4）**，但这一组在外层测试折上并不比原设置好：ResNet18 固定层 R1_base 0.696、R4_probmean 0.692（单种子，见 `all_configs_outer.csv`）。说明内层分数之间的差距（约 0.02）在噪声范围内，选择本身不稳定。
* **结论：** 主 notebook 的原设置已经接近这个数据量下能达到的水平；最终结论仍以未调参的主结果为准，调参作为敏感性分析报告。

**透明度阶段只完成了一部分：** 每组参数在外层折上的单种子成绩（`all_configs_outer.csv`），ResNet18 的 6 组 × 5 折全部完成；CNN 只完成了第 0 折（表中 `n_folds = 1`），之后手动停止。这一阶段只用于展示，不参与任何选择，所以不影响上表。
